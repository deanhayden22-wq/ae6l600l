ANSWER TO OPEN-HOLE 4
--------------------------------------------------------------------------------
Lookup 2 (0xAE6D4 / 0xAE6FC / 0xAE6E8 / 0xAE710) is NEITHER "the threshold" NOR
"a per-cylinder trim on one". It is the SIGMA MULTIPLIER: the dimensionless gain
applied to a tracked per-cylinder deviation statistic.

    threshold_A = clamp( baseline + K * deviation,          50.0,  359.0 )
    threshold_B = clamp( baseline + K * 1000.0 * deviation, 50.0, 1000.0 )

    K         = lookup 2, 18 RPM x 2 LOAD, float32, 3.45..3.60, DIMENSIONLESS
    1000.0    = lookup 3 (0xAE724 family), 1000.0 in every cell
    baseline  = per-cylinder tracked mean      -> [r9-16] = 0xFFFF8148
    deviation = per-cylinder tracked spread    -> [r9-8]  = 0xFFFF8150
    50 / 359 / 1000 = float consts 0x0D2D88 / 0x0D2D8C / 0x0D2D90

    threshold_A -> 0xFFFF8154        threshold_B -> 0xFFFF8158

THREE FACTUAL CORRECTIONS to the previous open-holes entry
--------------------------------------------------------------------------------
1. "Its result lands at [r9-40]" -- NO. Lookup 2 stores to [r9-44] = 0xFFFF812C.
   [r9-40] = 0xFFFF8130 is LOOKUP 3's result.

2. "consumed by the arithmetic at 0x043888-0x0438B0" -- NO. That block never
   reads [r9-44]. It reads [r9-32], [r9-92], [r9-24] and writes [r9-20]; it is
   the DEVIATION ESTIMATOR (block C). Lookup 2's result is first read at
   0x043ABE, some 560 bytes later.

3. "Units are knock-signal units ... not degrees" -- NO. K is DIMENSIONLESS. It
   multiplies a deviation, so it is a sigma count. The knock-signal domain in
   this function runs to several hundred, not 0..3.5; the clamps at 50.0 and
   359.0 sit in that domain, K does not.

--------------------------------------------------------------------------------
r9 IS NOT A STACK FRAME. It is a fixed RAM workspace base:

    0439BC literal = FFFF8158   ->  r9  = 0xFFFF8158  (loaded 0x0437B4)

THE LEVER (recorded, not proposed)
--------------------------------------------------------------------------------
The two 18-value load planes of lookup 2 are byte-identical (confirmed via
desc_types.read_table on 0xAE6D4 and 0xAE6E8), which is why "knock detection has
no load input" held up empirically while being false about the code. Because K
is a sigma multiplier, differentiating the planes is well-defined: LOWERING K in
a load band makes detection MORE sensitive there, raising it LESS. The load axis
breakpoints are 0.80 and 2.20 g/rev; RPM runs 800..7600 in 400 steps.
