WHAT IT IS, IN ONE PARAGRAPH
  A void, argument-less function that owns five cells of the RAM block at 0xFFFF805C..0xFFFF8074. While an
  enable bit (0xFFFF8075 bit1) is set it (1) advances a 0..3 step counter each call that two bits of the flag
  word 0xFFFF8080 are both set, (2) picks a step factor from one of 18 four-float ROM arrays by
  (mode, A-vs-3000.0, sel, counter), (3) keeps a running maximum of B and looks that maximum up in one of 12
  uint8 1-D tables chosen by (mode, sel), and (4) writes OUT = table * step * two factors owned by other
  functions -- or 0.0, or a ROM constant that is also 0.0 -- depending on three more bits of the flag word.
  When the enable bit is clear it zeroes the counter, the maximum and OUT.
  It calls no clamp routine and bounds neither OUT nor the step factor. Three things ARE bounded: the counter
  stops incrementing at 3, the peak can only rise while the bit stays set (a NaN peak excepted: the next
  maximum returns B), and the table value saturates at the first / last cell outside the 0..87.5 axis.
  The enable bit belongs to the sibling 0x042368, which the same runner calls two calls earlier. It sets the bit
  only while a hysteresis of B is on (on at B >= 1.56, off below 0.537) and F bit0 is set, and clears it when
  F bit0 is clear, after 88 calls, once W bit 0x4000 has been left set for 25 calls, or while W bit 0x0004 is
  set with 0x0002 clear. That sibling is decoded in SUPPORTING DECODES, and it changes what this function can
  put out: see WHAT THE CALIBRATION IN THIS BIN MAKES OF IT.

MECHANISM

    mode = (byte [0xFFFF65C5] == 1)                 ; via 0x022CF4, kept in frame+0
    B    = f32 [0xFFFF62F4]
    sel  = u8  [0xFFFF6810]
    en   = [0xFFFF8075] & 0x02
    W    = u16 [0xFFFF8080]

  1 counter [0xFFFF8074]
        if not en:                                             counter = 0
        elif (W & 0x0004) and (W & 0x0002) and counter < 3:    counter = counter + 1
        else:                                                  unchanged, not written
    One step per CALL while both W bits are set. The increment stops at 3. The compare is on the zero-extended
    byte, so any value 3..255 found in RAM is left exactly as it is (it is not pulled back to 3).

  2 step [0xFFFF8064]                   only when en; otherwise not written
        if mode:   family = LO if 3000.0 > A else HI           ; A == 3000.0 exactly gives HI
        else:      family = M0
        step = f32 ROM[ family[sel] + 4*counter ]              ; counter AFTER stage 1, zero-extended, unchecked
    family[sel] is one of 6 array bases: sel 1,2,3,4,5 or "other" (0, 6..255).

  3 peak [0xFFFF8070] and table [0xFFFF8060]
        if en:     peak  = peak if peak > B else B             ; 0x0BE960. Never decreases while en stays set,
                                                               ; except from NaN: "NaN > B" is false, so a NaN
                                                               ; peak is replaced by B on the next call
                   table = lookup1D( (D1 if mode else D0)[sel], x = peak )
        else:      peak  = 0.0                                 ; table is not written
    The lookup input is the peak just stored, not B. The lookup saturates: x < 0 returns the first cell,
    x >= 87.5 (and NaN) the last cell.

  4 OUT [0xFFFF805C]
        if not en:           OUT = 0.0
        elif W & 0x1000:     OUT = f32 ROM[0x0D2C90]           ; 0.0 in this ROM
        elif W & 0x2000:     OUT = 0.0
        elif W & 0x4000:     OUT = ((table * step) * [0xFFFF806C]) * [0xFFFF8068]
        else:                OUT is not written and keeps its previous value
    Priority is exactly that order: 0x1000 beats 0x2000 beats 0x4000.

  EDGE CASES

    * sel is compared for equality with 1..5 only; 0 and 6..255 all take the "other" case.
    * mode is "byte == 1", not "byte != 0": 2 or 0xFF behave as mode 0.
    * A counter above 3 on entry is never corrected. The array read then runs past the 4 entries
      (counter 0xFF reads base + 0x3FC). The only stores to 0xFFFF8074 that find_writers.py reports are the
      two in this function (042556, 04255C), which can only store 0..3, so this needs a cell that was never
      reset (NOT ESTABLISHED h).
    * OUT can be -0.0: a negative table value times a 0.0 step factor. Emulated (bits 0x80000000).
    * The stage-2 array is chosen with the CURRENT A every call, so the family can change between LO and HI
      while the counter is mid-sequence.
    * BOUNDS. No clamp routine is called, and nothing limits OUT, the step factor or the array index: with
      large foreign factors the product overflows and OUT saturates at -/+FLT_MAX (3.4028235e38, the
      round-toward-zero overflow result of fmul -- a property of the FPU, not a bound the code sets); an
      infinite factor gives -/+inf (both emulated). A counter of 0xFF is
      used as an index unchanged. Three things are limited:
        (a) the counter increment stops at 3                              042546-04254A
        (b) the peak is a running maximum: it cannot fall while F bit1    0BE960-0BE96E, stored at 0427F4
            stays set. That is a hold, i.e. a one-sided filter on B.
            Exception: a NaN peak (from a NaN B) is replaced by the next  emulated: check_nan_edge

        (c) the table value is end-saturated by the lookup's axis search  0BECAE-0BECB0, 0BECB4, 0BECD0-0BECDA

       review: imprecise -- the peak is a running-maximum hold and the lookup saturates.
       RIGHT: the reviewer. The blind text listed 042578 and 0BE960 as the only FP compares; the axis
       search has two more and they are what bounds the table value. Deciding evidence:
      0BECAE: F105  fcmp/gt fr0,fr1                 ; T = (axis[n-1] > x)
      0BECB0: 8F0E  bf/s 0x0BECD0                   ; T=0 (x >= last breakpoint, or NaN) -> last cell, fraction 0
      0BECB4: 8D0F  bt/s 0x0BECD6                   ; x below the first breakpoint -> first cell, fraction 0
      0BE960: F455  fcmp/gt fr5,fr4                 ; the maximum: the stored peak can only rise (NaN peak: fr5 = B wins)
       emulated: 0x0BE830 at -1e9, -inf, 1e9, +inf, NaN on all 12 descriptors returns the first / last cell.
       Two things the reviewer did not say, added here: the uint8 cell reader has an fcmp/eq as well
       (0BEB26), and the counter increment is itself limited to 3 (042548). What survives of the blind
       claim: no clamp routine, and no bound on OUT, the step factor or the array index.

  A34  blind: sel is "1..5 by comparing ... with thresholds 13.416, 18.048, 23.545, 32.543, 200.0 ... and 6
       on its bail-out path"; bail-out conditions "not decoded".
       review: imprecise -- the 200.0 rung stores 5; 6 comes from two byte tests and a second writer.
       RIGHT: the reviewer, on every point. Deciding evidence:
      023FFA: 8907  bt 0x02400C                     ; ratio > 200.0 -> 0x02400C
      02400C: E205  mov #5,r2
      02400E: 2120  mov.b r2,@r1                    ; the selector gets 5
      024014: 8011  mov.b r0,@(1,r1)                ; the 6 goes to 0xFFFF6811
      023F7A: 8801  cmp/eq #1,r0                    ; [0xFFFF65C0] == 1 -> 6
      023F80: 8802  cmp/eq #2,r0                    ; 0x0297A0 result == 2 -> 6
      024098: 2620  mov.b r2,@r6                    ; second writer, function 0x024094: 6, unconditionally
       emulated: 0x023EB8 against a model of every path, 7,920 cases; ratio 200.1 and 1000 give (5, 6).
       Added here: 0x0297A0 returns 2 exactly when byte [0xFFFF9704] != 0 (0297A0-0297AE).

  A35  blind: "the most negative table*step product is -24.9609375 * 1.25 = -31.201171875 (... peak <= 0)".
       review: imprecise -- the arithmetic is right but peak <= 0 with the bit set is not reachable.
       RIGHT: the reviewer. Deciding evidence:
      04246A: 2068  tst r6,r0                       ; T = 1 when W bit 0x0200 is clear
      04246C: 890A  bt 0x042484                     ; clear -> exit without setting F bit1
      042474: 2100  mov.b r0,@r1                    ; the only store that sets F bit1
      0BE800: F545  fcmp/gt fr4,fr5                 ; T = (hi > B): the bit goes on only at B >= 1.56
      0BE80C: F545  fcmp/gt fr4,fr5                 ; T = (hi - width > B): it goes off only at B < 0.537
       emulated chain 0x042368, 0x04248C, 0x042506: B = 0, 1.0, 1.55 leave the bit clear; B = 1.56 sets it
       with OUT -29.6655; hysteresis already on and B = 0.537 gives OUT -30.6726, B = 0.54 gives -30.6696
       (the reviewer's figure); minimum over 13,200 random passes -30.6726.
       Also right: OUT is +/-0 for sel outside 1..5 or counter 3 only on a call that takes the product path.
       Refinement from the re-check (neither earlier decode tried it): the floor needs B to be non-NaN on the
       call that sets the bit. Both compares treat NaN as "not greater":
      0BE800: F545  fcmp/gt fr4,fr5                 ; hi > NaN is false -> 0BE806 path: hysteresis ON, bit can be set
      0BE960: F455  fcmp/gt fr5,fr4                 ; NaN > B is false -> 0BE96A: the NaN peak is replaced by B
       emulated (check_nan_edge): B = NaN then B = 0 gives OUT -18.8965, then -31.201171875. So the reviewer's
       "-31.2 is not a reached value" holds only with premise (iii); 0x01F5F2 cannot make a NaN B from finite
       history (0x0BE8E4 finite for NaN / +-inf inputs, emulated), which moves the residual to NOT ESTABLISHED h.
