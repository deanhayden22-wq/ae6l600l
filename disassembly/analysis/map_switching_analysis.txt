================================================================================
SECTION 1: OVERVIEW — THE DECISION CHAIN (re-derived 2026-07-28)
================================================================================

The cruise/non-cruise system blends between two parallel sets of calibration
tables. A float at 0xFFFF90A8 is the blend weight: 0.0 = full Cruise,
1.0 = full Non-Cruise. It affects timing, fueling, knock limits, AVCS and
throttle response.

1.1  Four functions, called back-to-back from one parent
────────────────────────────────────────────────────────

  0605E6: B471  bsr 0x060ECC
  0605EA: B57C  bsr 0x0610E6
  0605EE: B597  bsr 0x061120
  0605F2: B5AC  bsr 0x06114E

  0x060ECC  evaluates the cruise CONDITION; maintains counter 0xFFFF90B2,
            resetting it to 0 the instant any gate fails
  0x0610E6  ARMS cruise: writes flag 0xFFFF90C4 once both dwell counters
            have reached their ROM thresholds
  0x061120  maintains counter 0xFFFF90B4 — the re-entry lockout, reset only
            on the falling edge of 0xFFFF90C4
  0x06114E  ramps the blend ratio 0xFFFF90A8 toward the requested end

0xFFFF90A8 has exactly ONE write site in the ROM:

  0611DE: D621  mov.l @(0x061264),r6
  0611E0: F60A  fmov.s fr0,@r6

1.2  Ramp direction and rate
────────────────────────────

  0611BE: C416  mov.b @(22,gbr),r0     ; GBR=0xFFFF90A8, +22 => 0xFFFF90BE
  0611C0: 2008  tst r0,r0
  0611C4: 8F04  bf/s 0x0611D0          ; flag != 0 -> SUBTRACT branch
  0611C6: F468  fmov.s @r6,fr4         ; delay slot: fr4 = current ratio
  0611CA: F928  fmov.s @r2,fr9         ; fr9 = [0xD9B40] = 0.008
  0611CE: F490  fadd fr9,fr4           ; flag == 0: ratio += 0.008
  0611D2: F828  fmov.s @r2,fr8         ; fr8 = [0xD9B44] = 0.008
  0611D4: F481  fsub fr8,fr4           ; flag != 0: ratio -= 0.008
  0611DA: 420B  jsr @r2                ; 0xBE56C = clamp(fr4, fr5=0.0, fr6=1.0)

  So 0xFFFF90BE == 1 means "cruise requested" and drives the ratio DOWN
  toward 0.0 (Cruise). 0xFFFF90BE == 0 drives it UP toward 1.0 (Non-Cruise).
  Rate is +/-0.008 per invocation, symmetric — 125 invocations for a full
  swing. The scheduler rate of the 0x60562 parent is NOT established, so
  this cannot be converted to seconds. Do not state one.

1.3  Cruise-request flag (0xFFFF90BE), written at 0x0611BC
──────────────────────────────────────────────────────────

  flag = 0 (force Non-Cruise) if either fault byte is non-zero:
      0x029AA0 returns 2 when [0xFFFF972E] != 0
      0x0297B0 returns 2 when [0xFFFF9705] != 0
  otherwise a selector byte at 0xD9AC4 chooses the source:
      == 1            -> flag = 1 unconditionally
      == 3            -> flag = ([0xFFFF9113] == 1)
      == 4            -> flag = ([0xFFFF9113] == 0)
      < 1 or > 4      -> flag = ([0xFFFF90C4] == 1)     <-- THIS ROM

  0xD9AC4 is 0 in stock and in every 20.x rev, so the selector always falls
  through to the 0xFFFF90C4 branch.

1.4  Arming (0x0610E6) — the two dwell counters
───────────────────────────────────────────────

  0610E8: 8541  mov.w @(2,r4),r0       ; r4 = 0xFFFF90B0, so counter A @ 0xFFFF90B2
  0610EC: 6251  mov.w @r5,r2           ; r2 = [0xD9AD8] = 250
  0610EE: 3022  cmp/hs r2,r0           ; T = (counterA >= 250)
  0610F0: 8B0E  bf 0x061110            ; fail -> write 0
  0610FA: F985  fcmp/gt fr8,fr9        ; T = ([0xD9B2C]=4.0 > [0xFFFF90EC])
  0610FC: 8903  bt 0x061106            ; below 4.0 -> skip the 0xFFFF90B0 test
  061102: 3262  cmp/hs r6,r2           ; T = ([0xFFFF90B0] >= 1)
  061104: 8904  bt 0x061110            ; fail -> write 0
  061106: 8542  mov.w @(4,r4),r0       ; counter B @ 0xFFFF90B4
  06110A: 6251  mov.w @r5,r2           ; r2 = [0xD9ADA] = 375
  06110C: 3022  cmp/hs r2,r0           ; T = (counterB >= 375)
  06110E: 8903  bt 0x061118            ; pass -> write 1
  061118: E201  mov #1,r2
  06111C: 000B  rts
  06111E: 2620  mov.b r2,@r6           ; r6 = 0xFFFF90C4

  Counter B (0x061120) is reset ONLY on the 1->0 edge of 0xFFFF90C4, latched
  through 0xFFFF911A. It is therefore a re-entry LOCKOUT: after cruise drops,
  375 counts must elapse before it can arm again.

1.5  The condition itself (0x060ECC) — why cruise is rare
─────────────────────────────────────────────────────────

  The governing test compares a torque-domain value [0xFFFF85E4] against two
  RPM-indexed curves forming a hysteresis band:

  060F56: F8D6  fmov.s @(r0,r13),fr8   ; r13=0xFFFF9120, -44 => 0xFFFF90F4 (SET curve)
  060F58: F8E5  fcmp/gt fr14,fr8       ; T = (curve > [0xFFFF85E4])
  060F5A: 8B02  bf 0x060F62
  060F5C: E001  mov #1,r0
  060F60: C064  mov.b r0,@(100,gbr)    ; GBR=0xFFFF90B2, +100 => 0xFFFF9116 = 1
  060F64: F8D6  fmov.s @(r0,r13),fr8   ; -40 => 0xFFFF90F8 (CLEAR curve)
  060F66: F8E5  fcmp/gt fr14,fr8       ; T = (curve > [0xFFFF85E4])
  060F68: 8901  bt 0x060F6E            ; still below -> hold
  060F6C: C064  mov.b r0,@(100,gbr)    ; else 0xFFFF9116 = 0

  Curves come from 1D descriptors 0xAF630 (SET) and 0xAF644 (CLEAR), axis
  0xD9BA4 / 0xD9C04 (float RPM x16), data 0xD9BE4 / 0xD9C44 (uint16 x16,
  descriptor multiplier 0x3BCCCCCC = 0.00625, offset 0.0).

  Selector [0xFFFF5DB5] (cl_ol_gate_flag) picks between three descriptor
  sets — 0xAF630/0xAF644, 0xAF658/0xAF66C, 0xAF680/0xAF694 — but all three
  are BYTE-IDENTICAL in stock and every 20.x rev, so the choice is inert.

  Values in descriptor units (raw x 0.00625):

    RPM     300   400..1600   2000   2400   2800   3200   3600+
    SET     340      130       110     90     55      0      0
    CLEAR   350      180       180    160    140    105     70 -> 0 at 3600

  The SET curve is ZERO from 3200 RPM up and the CLEAR curve is ZERO from
  3600 up. Cruise therefore CANNOT be entered above 3200 RPM at any torque,
  and is force-cleared above 3600 RPM.

  MEASURED 2026-07-28 against 213 min of 20.19/20.19b logs, applying only the
  two gates that are loggable (RPM here, MAF in Section 1.6):

    hard floor on NON-cruise time ............ 27.5%
    upper bound on cruise-eligible time ...... 72.5%  (torque gate excluded)
    highway (>=50 mph) above the RPM ceiling . 55.5%
    city (5-50 mph) above the RPM ceiling ....  8.6%

  So the RPM ceiling is decisive ON THE HIGHWAY and marginal in the city; it
  does NOT make cruise globally rare. An earlier draft of this section said it
  did — that was an overstatement written before the logs were checked. The
  true residency is somewhere below 72.5% and cannot be pinned down here,
  because [0xFFFF85E4] is not an SSM channel. Quote the bound, not a number.

  Raw table values (20800, 28800, 54400, ...) are divisible by 128 and match
  the raw-torque encoding family used by the per-gear torque cap (44800 =
  350). That correspondence is SUGGESTIVE, not proven: the exact physical
  unit of 0xFFFF85E4 is unverified. Its writers are at 0xBC61C-0xBCA3E.

1.6  Other gates on the same condition (all must hold)
──────────────────────────────────────────────────────

    [0xFFFF90E0] >= [0xD9B30] (-40.0)      — a sensor floor, effectively always true
    [0xFFFF9116] == 1                      — the RPM/torque band above
    [0xFFFF9117] == 1                      — MAF gate: set below 45 g/s
                                             ([0xD9B34]), clear at 50 g/s
                                             ([0xD9B38]). 0xFFFF90F0 is loaded
                                             from 0xFFFF63C4 = MASS AIRFLOW
                                             g/s at 0x060592-0x060598.
    [0xFFFF5E96] == 0
  Any failure jumps to 0x0610CE, which zeroes counter A and restarts the dwell.

1.7  Application
────────────────

  Task 32 (0x4004A) reads the ratio and linearly interpolates:

  0401D6: F9F8  fmov.s @r15,fr9        ; fr9 = ratio, saved from [0xFFFF90A8]
  0401DA: F6C6  fmov.s @(r0,r12),fr6   ; -28 => Non-Cruise result
  0401DC: F862  fmul fr6,fr8           ; fr8 = ratio * NonCruise
  0401DE: F09D  fldi1 fr0
  0401E0: F091  fsub fr9,fr0           ; fr0 = 1.0 - ratio
  0401E4: F9C6  fmov.s @(r0,r12),fr9   ; -32 => Cruise result
  0401E6: F89E  fmac fr0,fr9,fr8       ; fr8 += (1-ratio) * Cruise

      result = ratio * NonCruise + (1 - ratio) * Cruise

  Descriptor -> table bindings, read out of the descriptor bytes:
    0xAE31C -> 0xD4714  Base Timing Primary Cruise
    0xAE338 -> 0xD48D4  Base Timing Primary Non-Cruise
    0xAE354 -> 0xD4A94  Base Timing Reference Cruise
    0xAE370 -> 0xD4C54  Base Timing Reference Non-Cruise

  Cruise vs Non-Cruise cell differences (via scripts/defs.py, 2026-07-28):

    Base Timing Primary              0/306 differ  (stock: 121)
    Base Timing Reference (AVCS)     0/306         (stock: 121)

  The decision calibration itself (0xD9AC0-0xD9E30) is byte-identical to

Four further functions implement the ADJACENT timing blend, and are what
Sections 3-8 document:

  Task 50 @ 0x3F368: per-cylinder timing summation
  Task 32 @ 0x4004A: blend application (Section 1.7 above)
  Task 31 @ 0x3FFD6: blend scratch bounds
  Task 33 @ 0x40918: timing workspace init / ECT descriptor selection

Execution order: 50 → 32 → 31 → 33 (within the ignition timing pipeline)

  -0x24   float   FFFF7F3C     Blend correction scratch (task31 output)

================================================================================
SECTION 3: TASK 50 - MAIN MAP SWITCH EVALUATOR (0x3F368)
================================================================================

Task 50 is the largest function (~1300 instructions). It operates
with GBR = 0xFFFF7E90 and implements the full cruise/non-cruise
decision engine.

Inputs loaded at entry:
  fr12 = rpm_current       (FFFF6624)
  fr14 = torque_ratio      (FFFF62F8)
  fr15 = vehicle_speed     (FFFF65FC)  -- see corrections.md item 9; the old
                                          "load_current" label here is stale.
                                          Note this file's own threshold list
                                          below already reads it as a speed.
                                          OPEN: D2A14/D2A18 hold 550/1300,
                                          which are not km/h-shaped, so what
                                          those two gate is unresolved.
  fr8  = ect_current       (FFFF6350) → saved to stack
  r12  = flkc_mode_byte    (FFFF8F16)
  r11  = timing_state_A    (FFFF8F24)
  r10  = timing_state_B    (FFFF85D7)
  r14  = clutch_state      (FFFF5BE3)
  r13  = accel_state       (FFFF65BF)
  r9   = sched_status      (FFFF7D18)

The function also reads:
  FFFF7F68 = ECT-based blend correction (from task33)
  FFFF7FBC = previous timing output

3.1  Delay Counter Logic (GBR+0x71, GBR+0x72)
──────────────────────────────────────────────

Two independent countdown timers gate the switching:

  Counter A (GBR+0x71): Loaded from D2974 (ROM byte) on state change.
    Decrements each cycle while > 0. Only when counter A expires AND
    the clutch/accel conditions are met does the switching proceed.

  Counter B (GBR+0x72): Same mechanism, loaded from D2975.
    Gates the second switching path (secondary threshold check).

  The uint16 counters at D29AC-D29B2 (50/38/100/38) are the counter
  initialization values used elsewhere in the map switch framework
  (cross-referenced by the timer reload paths in check_engine_running @ 0x022CF4).

3.2  Primary Switching Path (0x3F462 → 0x3F49A)
────────────────────────────────────────────────

Triggered when flkc_mode_byte (r12) == 1 (non-idle, non-FLKC):

  The ratio source is read from FFFF7F04 (pre-computed ratio):
    GBR = FFFF7E90 → offset -0x40+GBR = FFFF7F04 (approximation unclear)
    → loads fr15 = pre-existing blend ratio

3.3  Low-RPM Path (0x3F470 → 0x3F49A)  — COMPARISONS CORRECTED 2026-07-28
──────────────────────────────────────────────────────────────────────────

Conditions (ALL must be true):
  1. timing_state_A (r11, [0xFFFF8F24]) == 1
  2. the 0x05EB32 helper returned 1
  3. timing_state_B (r10, [0xFFFF85D7]) == 1
  4. ECT-based blend correction [0xFFFF7F68] <= 0.0
  5. RPM < 2000 (0xD2A08)

  03F488: F855  fcmp/gt fr5,fr8   ; T = ([0xFFFF7F68] > 0.0)
  03F48A: 8906  bt 0x03F49A       ; > 0 -> LEAVE.  continue requires <= 0.0
  03F490: F8C5  fcmp/gt fr12,fr8  ; n=8,m=12: T = (fr8 > fr12) = (2000 > RPM)
  03F492: 8B02  bf 0x03F49A       ; RPM >= 2000 -> LEAVE.  continue requires < 2000

  Both were stated inverted before ("> 0.0", "RPM > threshold"). This is the
  LOW-rpm path, not a high-load path.

If all conditions met → loads fr15 from FFFF7F1C

3.4  Stationary / Idle Classifier (0x3F49A → 0x3F584)  — REWRITTEN 2026-07-28
──────────────────────────────────────────────────────────────────────────────

This is NOT the cruise/non-cruise decision (that is Section 1). Every
comparison in the original version of this section was inverted. Re-derived
from bytes; `fcmp/gt FRm,FRn` sets T = (FRn > FRm), and `0xFnm5` has n in
bits 8-11, m in bits 4-7.

Register bindings at entry: fr12 = [0xFFFF6624] RPM, fr14 = [0xFFFF62F8]
torque ratio, fr15 = [0xFFFF65FC] vehicle speed, stack@0 = [0xFFFF6350] ECT,
r5 = extu.b [0xFFFF5BE3] clutch_state.

  03F49E: F8E5  fcmp/gt fr14,fr8  ; T = (0.8798 > torque_ratio)   [0xD2A0C]
  03F4A0: 8B70  bf 0x03F584       ; continue requires torque_ratio <  0.8798
  03F4A6: F8F5  fcmp/gt fr15,fr8  ; T = (2.0 > vehicle_speed)     [0xD2A10]
  03F4A8: 8B6C  bf 0x03F584       ; continue requires speed       <  2.0
  03F4AE: F8C5  fcmp/gt fr12,fr8  ; T = (550 > RPM)               [0xD2A14]
  03F4B0: 8968  bt 0x03F584       ; continue requires RPM         >= 550
  03F4B6: F8C5  fcmp/gt fr12,fr8  ; T = (1300 > RPM)              [0xD2A18]
  03F4B8: 8B64  bf 0x03F584       ; continue requires RPM         <  1300

  03F4CA: 8B5B  bf 0x03F584       ; continue requires clutch_state == 0

3.5  Secondary Switching Path (0x3F584 → 0x3F5D6)
──────────────────────────────────────────────────

If the standard path fails, a secondary set of thresholds is checked:

  Calibration addresses for secondary path:
    D2A20, D2A24, D2A28, D2A2C, D2A30, D2A3C

  These are NOT in the ECUFlash definitions yet. They appear to be
  alternative thresholds for a less aggressive switching condition
  (possibly used during warmup or transient conditions).

  The same gate structure applies: counter B (GBR+0x72) must be > 0
  and the inhibit must be clear.

  If secondary passes → loads fr15 from D2A3C and proceeds.

3.6  Timing Summation (0x3F618 → 0x3F6A8)
──────────────────────────────────────────

When the byte at D2976 == 90 (0x5A), the function enters a full
timing summation path that adds/subtracts multiple correction terms:

  final_timing = timing_blend_base (FFFF7F0C)
               + blend_correction_A (FFFF7F68 from stack @4)
               + blend_correction_B (FFFF7F6C)
               + blend_correction_C (FFFF7F74)
               - stack_correction   (stack @8)
               - base_timing_offset (FFFF8000)
               + ECT_timing_comp    (FFFF81EC)
               + correction_28      (FFFF8028)
               - correction_38      (FFFF8038)
               + correction_3C      (FFFF803C)
               + correction_5C      (FFFF805C)
               - correction_84      (FFFF8084)
               + correction_B4      (FFFF80B4)
               + correction_C4      (FFFF80C4)
               - correction_E8      (FFFF80E8)
               + correction_F0      (FFFF80F0)
               + accumulator_88     (FFFF8088)
               + workspace_81DC     (FFFF81DC)

This mirrors the final timing aggregation logic from ignition_timing_analysis.txt
(task 48), meaning task 50 is computing what the BLENDED timing would be
by summing all the same correction terms used in the non-blended path.

The result is stored into 4 per-cylinder timing values:
  fr9/fr13/fr12/fr15 → cylinder 1/2/3/4 blended timing

Each per-cylinder value adds the corresponding offset from the
FFFF8088 knock_retard_accum (per-cylinder knock retard accumulator) and
FFFF81DC per_cyl_base_corr (per-cylinder base timing correction).


================================================================================
SECTION 4: TASK 32 - BLEND RATIO APPLICATION (0x4004A)
================================================================================

Task 32 applies the map ratio to descriptor lookups. It uses
GBR = FFFF7F0C.

4.1  Inputs
───────────
  fr12 = rpm_current (FFFF6624)
  fr14 = ENGINE LOAD (FFFF63F8)   <-- CORRECTED 2026-07-28, was "iat_current".
         corrections.md item 9 settled 0xFFFF63F8 as engine load. This is also
         what makes the descriptor calls coherent: 0xAE31C..0xAE370 are
         Load x RPM tables, and Section 4.4 passes fr4 = fr14 as axis 0 and
         fr5 = [0xFFFF7F4C] (engine speed) as axis 1.
  fr15 = FFFF679C — as float
  fr9  = initial value from check_engine_running → either
         TimBlend_RPMLimit (D2B14 = 6000) or TimBlend_MinRatio (D2B10 = 0.0)
  r13  = idle_mode_flag (FFFF7BE2)

4.2  SI-Drive Gate
──────────────────
  Reads FFFF8075 (si_drive_mode), checks bit 1 (SI-DRIVE S# mode).
  If SI-DRIVE S# is not active → skips to ratio store at 0x40160.
  Also checks bit 0 (SI-DRIVE I mode).

  SI-DRIVE determines whether the ECU uses the non-cruise tables at all.
  In S# mode (bit 1 set), non-cruise is always active (ratio → 1.0).
  In I mode (bit 0 set), the switching logic is enabled.
  In S mode (neither), it falls through to the cruise-only path.

4.3  Counter Gate (GBR+0x54)  — CORRECTED 2026-07-28
────────────────────────────────────────────────────
  Reads a uint16 at GBR+0x54 = FFFF7F60 and compares against [0xD29D4] = 88.

  04008E: C52A  mov.w @(84,gbr),r0
  040094: 3026  cmp/hi r2,r0        ; T = (counter > 88), unsigned
  040096: 8963  bt 0x040160

  It does NOT "skip to ratio = 0.0". 0x040160 stores fr15 into 0xFFFF7F4C,
  i.e. it selects which ENGINE SPEED value feeds the base-timing lookups —
  [0xFFFF679C] on this path versus [0xFFFF804C] on the path at 0x0400B2.
  The blend ratio (0xFFFF90A8) is untouched by this branch.

4.4  Descriptor Lookups  — AXIS INPUTS CORRECTED 2026-07-28
───────────────────────────────────────────────────────────
  Four 2D descriptors are evaluated via table_desc_2d_typed (0xBE8E4), each
  with fr4 = [0xFFFF63F8] (ENGINE LOAD) and fr5 = [0xFFFF7F4C] (ENGINE SPEED):

    Descriptor @ 0xAE31C -> table 0xD4714  Base Timing Primary Cruise
    Descriptor @ 0xAE354 -> table 0xD4A94  Base Timing Reference Cruise
    Descriptor @ 0xAE338 -> table 0xD48D4  Base Timing Primary Non-Cruise
    Descriptor @ 0xAE370 -> table 0xD4C54  Base Timing Reference Non-Cruise

  Table addresses read out of the descriptor bytes, e.g.
  0xAE31C = 0011 0012 000D4688 000D46CC 000D4714 04000000 3EB40000 C1A00000
  = 17 x 18, axis0 0xD4688 (load), axis1 0xD46CC (RPM), data 0xD4714.

  The previous text said the inputs were "IAT and the map ratio". Both were
  wrong: the ratio is not a lookup axis, it is applied afterwards as the
  blend weight in Section 4.5.

  Results stored as:
    fr15 = cruise primary timing
    fr13 = cruise reference timing
    fr12 = non-cruise primary timing
    fr8  = non-cruise reference timing (saved to stack @8)

4.5  Blending Formula
─────────────────────
  The blend uses the standard linear interpolation:

    fr14 = desc0_result  (cruise value)
    fr15 = desc0_result - desc1_result  (delta)
    → float_max(fr15, 0.0) → clamp negative
    → fr14 = fr14 - fr0 * blend_correction  (fmac)

  This is stored to GBR-0x20 (FFFF7F0C - 0x20 = FFFF7EEC).

  Same process for desc2/desc3:
    fr14 = desc2_result
    → fmac blend → store to GBR-0x1C (FFFF7EF0)

4.6  Smoothing & Ramping
─────────────────────────
  The blend itself (0x4001D6-0x4001EA, quoted in Section 1.7) is:

    result = ratio × NonCruise + (1.0 - ratio) × Cruise

  where ratio = [0xFFFF90A8], loaded at task-32 entry (0x04006A) and saved to
  stack@0. Equivalent to cruise + (noncruise - cruise) × ratio. The result is
  stored to GBR-0x08 = 0xFFFF7F58, with the previous cycle at 0xFFFF7F5C.

  First-cycle initialization check:
    if GBR+0x56 (byte) == 0 → copy current to previous, set flag to 1

  Deviation check against TimBlend_CorrThreshold (D2B08 = 44.0°):
    If |current - previous| > 44° → average and scale by 0.5
    This prevents sudden large timing jumps during transitions.

  Idle mode special path (r13 == 1):
    Calls FUN_0xBEA40 with:
      fr4 = current timing
      fr7 = ramp rate constant (from literal pool = 0x3EB40000 ≈ 0.35)
      fr6 = TimBlend_HalfRatio (D2B0C = 0.5)
      fr5 = previous timing (from GBR-0x18)
    This implements a gentle ramp during idle transitions.

SECTION 5: TASK 31 - BLEND RATIO BOUNDS (0x3FFD6)
================================================================================

Task 31 is a simple bounds checker / state machine gate.

Inputs:
  fr14 = blend_ratio_workspace_A (FFFF9230)
  fr15 = blend_ratio_workspace_B (FFFF9234)
  fr12 = blend_timing_ws_A       (FFFF9164)
  fr13 = blend_timing_ws_B       (FFFF9168)
  r14  = blend_state_flag         (FFFF91F9, byte)

Calls flkc_state_flag_reader_slot15 @ 0x2999C (FFFF971B convergence check) → r0 = state

5.1  Engine State = 2 (cranking/starting)
─────────────────────────────────────────
  → Sets fr8 = 1.0 (fldi1), stores to FFFF7F3C (blend_output_scratch)
  → Jumps to epilogue. During cranking, ratio is forced to 1.0 (non-cruise).

5.2  Floor Check
────────────────
  Loads fr8 from TimBlend_RatioFloor (D2B18 = 0.0).
  Checks if fr14, fr15, fr12, fr13 are ALL > floor.
  If any is at or below floor → skip to epilogue (preserve current ratio).

5.3  Blend State = 1 (active blending)
──────────────────────────────────────
  Reads FFFF7F3C, subtracts TimBlend_RatioCeiling (D2B1C = 1.0).
  Calls float_max(result, 0.0) at 0xBE960.
  Stores clamped result back to FFFF7F3C.

  CORRECTION (2026-07-26, supersedes the 2026-04 note): BE960 = max(FR4, FR5).
  The operation is:
    FFFF7F3C = max(FFFF7F3C - 1.0, 0.0)
  This produces a NON-NEGATIVE value: how far the blend ratio exceeds 1.0,
  floored at 0. FFFF7F3C is a scratch variable — the result is used
  downstream as a correction term, not as the final blend ratio itself.

  History of this line, because it has been wrong twice:
    - Originally described as "ensures blend ratio never exceeds 1.0".
    - 2026-04 changed it to min() and "non-positive value (how far below
      1.0)". That was the backwards-operand error; it was wrong.
    - Verified from bytes 2026-07-26: F455 = fcmp/gt FR5,FR4 sets
      T = (FR4 > FR5), and the taken path keeps FR4 — so BE960 is max().
  See docs/corrections.md item 1.

SECTION 6: TASK 33 - TIMING WORKSPACE INIT (0x40918)
================================================================================

Task 33 is a dispatcher that calls three sub-functions:

  BSR 0x40A9C: Sub-function A — ECT-based descriptor selection
  BSR 0x40AF6: Sub-function B — Additional workspace setup
  BSR 0x41030: Sub-function C — Cylinder-specific timing init
  BRA 0x410D4: Sub-function D — Final dispatch (tail call)

6.1  Sub-function A (0x40A9C → appears at 0x4092A)
───────────────────────────────────────────────────
  GBR = FFFF7FD4 (timing_ws_gbr)

  Reads:
    throttle_position (FFFF65C0)
    FFFF85D7 (timing state byte)
    timing_ws_scratch (FFFF90BE)
    timing_ws_state   (FFFF8E7E)

  Selects between descriptor pairs based on throttle state and engine state:

    State matrix:
      throttle=0, engine_running=0 → desc @ 0xADB60 (desc_timing_blend_1)
      throttle=0, engine_running=1 → desc @ 0xADB4C (desc_timing_blend_0)
      throttle=1, engine_running=0 → desc @ 0xADB88 (desc_timing_blend_3)
      throttle=1, engine_running=1 → desc @ 0xADB74 (desc_timing_blend_2)

  The descriptor is evaluated via table_desc_1d_float (0xBE830) with
  fr4 = ect_current. Result stored to FFFF7F2C.

6.2  Sub-function at 0x403C4 (ECT correction)
──────────────────────────────────────────────
  Reads ect_current (FFFF6350) and timing_ws_scratch (FFFF90BE).
  Similar descriptor selection logic with descriptors:
    0xADBD8, 0xADBC4, 0xADC00, 0xADBEC

  Result stored to FFFF7F68 (ECT blend correction, used by task 50).

6.3  Sub-function at 0x40420 (timing blend table lookup)
────────────────────────────────────────────────────────
  Reads:
    iat_current (FFFF63F8)
    FFFF6364 (ect_startup — NOT atmospheric pressure, see merpmod_sd_port_analysis correction)
    rpm_current (FFFF6624)

  Evaluates descriptor @ 0xAE38C via table_desc_2d_typed.
  Result stored to FFFF7F70.

  Then evaluates descriptor @ 0xADC14 via table_desc_1d_float
  with fr4 = FFFF6364 (ect_startup, NOT atmospheric pressure).
  Multiplies result by FFFF7F70, stores to FFFF7F6C.

  This appears to be an atmospheric/altitude compensation for the
  timing blend.

SECTION 11: SUMMARY OF FINDINGS
================================================================================

0. CORRECTED 2026-07-28 — the cruise/non-cruise DECISION is not in tasks
   50/32/31/33 at all. It is the 0x60ECC / 0x610E6 / 0x61120 / 0x6114E chain
   documented in Section 1, calibrated at 0xD9AC4-0xD9E26, and the blend
   ratio is 0xFFFF90A8. Tasks 50/31/33 are adjacent timing code. Task 32 is
   the one genuine link: it APPLIES the ratio (Section 1.7 / 4.5).

1. Task 50 is ~1300 instructions with multiple paths, but they are timing
   paths. Its 0xD2A08-0xD2A1C gates form a stationary/idle classifier
   (Section 3.4), not a cruise selector, and every comparison in the
   original write-up was inverted.

2. The SI-DRIVE reading in Section 4.2 is UNVERIFIED and probably wrong: the
   bit tests at 0x040098/0x0400AC select which engine-speed source feeds
   0xFFFF7F4C, and neither branch writes 0xFFFF90A8. This car has no
   SI-Drive input (see docs/ and project memory). Do not build on it.

3. There is a secondary set of thresholds at D2A20-D2A3C that are NOT yet
   in the ECUFlash definitions. In 20.19c D2A20/D2A24/D2A28/D2A2C/D2A3C all
   read 0.0, so that path is inert. They provide alternative criteria for the
   Section 3.4 classifier, not for cruise switching.

4. The byte at D2976 == 90 (0x5A) selects between a simple timing blend
   and a full per-cylinder timing summation that mirrors the ignition
   timing pipeline.

5. The 44° deviation threshold (D2B08) prevents sudden timing jumps
   during cruise/non-cruise transitions — a safety feature.

6. 10 new descriptors identified (ADB4C-ADC14) for ECT-based blend
   corrections, plus 5 new descriptors (AE31C-AE38C) for the
   IAT×ratio blend application tables.

7. ~15 previously unnamed RAM addresses now identified (Section 8).

8. New calibration addresses D2A20-D2A3C and D2974-D2976 need
   ECUFlash definitions added.
