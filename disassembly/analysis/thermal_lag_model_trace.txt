ANSWER
--------------------------------------------------------------------------------
The five unnamed RPM x load tables from slice 1 are not five maps. They are the
pieces of ONE model: a load x RPM base quantity, multiplied by a knock-derived
uplift, then pushed through TWO cascaded first-order lag filters whose
coefficients differ for rising vs falling, with the filtered output compared
against a **930.0** trip point.

    0xAD960 / 0xAD97C   the base quantity, 390..866 / 390..1138
    0xAC60C             knock-derived uplift, 1.0000 .. 1.0469
    0xAD998 / 0xAD9B4   RISING / FALLING filter coefficient, 0.0117 .. 0.1094
    0xAD9D0             second-stage coefficient, flat 0.0100

None of the five, nor 0xAC60C, nor any constant below, has an `address=` entry in
the project XML.

1.0469 -- so the knock workspace can raise the target by up to **+4.7%**.

WHAT THIS IS -- stated as inference, not as a name
--------------------------------------------------------------------------------
Every property lines up with an **exhaust-gas / catalyst temperature model
driving open-loop enrichment for component protection**:

* the modelled quantity spans 390..1138 on a load x RPM base map;
* it is pushed through a two-stage thermal lag with SEPARATE heating and cooling
  time constants -- the standard way to model exhaust and catalyst mass;
* ignition retard raises it, via the knock-workspace uplift, by up to 4.7%;
* it trips a flag at **930.0**, a textbook catalyst/turbine protection limit;
* the enclosing module's GBR is 0xFFFF798C, which the repo labels
  `ol_enrichment_accum`.

**No name is asserted.** Nothing in the ROM or the XMLs states units, and the
repo's own label on 0xFFFF798C is a project guess -- and a CONFLICTING one: the
Ghidra script carries BOTH `ol_enrichment_accum` (line 1855) and
`timing_state_var` (line 2636) for that address. Settling the identity means
tracing what consumes byte[0xFFFF79FC].
