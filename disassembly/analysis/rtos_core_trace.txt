HEADLINE
--------------------------------------------------------------------------------
1. 0x00317C(r4) returns SR & 0xF0 in r0 and loads SR := r4 only when r4 is
   above that field. It reads no RAM. It is not an accessor of anything.
2. 0x003190(r4) loads SR := r4. When r4 == 0 it then tail-jumps to 0x003664,
   which switches tasks if word [0xFFFF128C] != word [0xFFFF128E]. The two are
   a bracket: 404 call sites of the first, 382 of the second (270 jsr and 112
   jmp), in the same 239 census functions. The level passed is 0x10 at 365
   sites, 0x90 at 25, 0xE0 at 8 and 0xB0 at 6. The bracket does NOT keep the
   caller's M, Q, S or T: what comes back is SR = (entry SR) & 0xF0.
3. Level 0x10 is not about interrupts. The interrupt exit at 0x002BD4 refuses to
   switch tasks when the interrupted code ran with a non-zero mask field
   (0x002C02..0x002C12), and so does the activation service 0x002EDC for its
   caller's mask field (0x002F20..0x002F2A). Raising the mask to 1 therefore
   holds off PREEMPTION. What makes a switch due in the meantime is 0x003206,
   called by 0x002EDC: it queues the id and, when the id's index is above byte
   [0xFFFF1288], raises that byte and sets word [0xFFFF128E] (0x003244..
   0x00324C). 0x003190(0) is where the held-off switch is finally taken.
4. 0x002B8C is called from exactly 118 places: the 118 stubs installed in
   vectors 64..231 of the table at VBR = 0x000FFC50. It counts the interrupt in
   [0xFFFF1290], pushes r2-r7, fr0-fr11, FPSCR and FPUL, and RETURNS the address
   0x002BD4 in r0. It dispatches to nothing. The stub makes that address the
   handler's return address, so every handler's rts lands on the common exit.
   The stubs differ in one long only: the handler address at stub+16.
5. 0x00E6E4(r4, r5, r6) posts nothing and touches no queue. It is
   word@r4 := r6 ? word | r5 : word & ~r5 with SR held at 0x00E0. All 136 call
   sites pass one of twelve addresses 0xFFFFF42E..0xFFFFF76C in r4 (on-chip
   register space). It does not reference 0xFFFF2060 / 0xFFFF2064, is not on the
   0x010800 path, and 0x010800 is not on its path.
6. The block at 0xFFFF2060 is not a queue either. 0x010B2A keeps five 12-byte
   records {code, first datum, hit count}, one per distinct 16-bit code, plus a
   "last code / last datum" pair at 0xFFFF20A0 / 0xFFFF20A4. Nothing in
   0x010B2A removes a record. 0x010800, the only way into it, is a general
   {code, datum} log with 21 call sites: after 9 of them the caller goes to
   the endless loop at 0x00FBA4, after the others it carries on.

CONTRACT
  in    r4  = SR value wanted. Every call site passes 0x10, 0x90, 0xB0 or 0xE0.
  out   r0  = SR & 0xF0 as it was on entry (the mask field, still in bits 7..4).
  SR    r4 >u (SR & 0xF0):  SR := r4 & 0x3F3  -- the whole register.
        otherwise:          SR unchanged, except T := 0 (left by the compare).
  r5 is overwritten with 0x000000F0. No memory is read or written. No stack.
MECHANISM
  cur = SR & 0xF0
  r0  = cur
  if (uint32)r4 > cur:  SR = r4
  return
  Edge cases, each emulated:
    r4 == cur             not raised (the compare is strict).
    r4 <  cur             not raised: the routine never lowers the mask for a
                          value of the form 0xN0.
    r4 = 0x01, cur = 0    "raised": SR := 0x001. Mask still 0, T = 1. The compare
                          is on all of r4, not on r4 & 0xF0.
    r4 = 0x100, cur=0xF0  "raised": SR := 0x100. The mask DROPS to 0. No call
                          site passes anything but 0x10 / 0x90 / 0xB0 / 0xE0.
    raise path            M, Q, S, T are taken from r4 (all 0 for the four
                          levels in use), so the caller's T is lost either way.
    as half of the pair   r0 carries only SR & 0xF0, and 0x003190 loads the
                          whole of SR from it. After 0x00317C(level) ...
                          0x003190(r0) the caller has SR = (entry SR) & 0xF0:
                          its M, Q, S and T are gone. (0x00E6E4 is different:
                          it puts back the exact entry SR.)

==== FUNCTION 0x003190 .. 0x0031A8  (12 instructions, 382 call sites in 239 census functions) ====
================================================================================
CONTRACT
  in    r4 = SR value to load. Call sites pass back what 0x00317C returned.
  SR    := r4 & 0x3F3 on every path (a delay slot on each of the three exits).
  r4 != 0   return. r0 untouched. No memory read.
  r4 == 0   rec = [0xFFFF12A0];  b = (int8) rec[1]

            else:    TAIL-jump to 0x003664 with SR = 0. 0x003664 returns r0 = 0
                     to the original caller -- at once if no switch is due,
                     otherwise when this task is next resumed.
            r5 = 0xFFFF1288 and r6 are overwritten on this path.
  382 sites: 270 jsr and 112 jmp (callers that end with it tail-call it). Six
  of the jsr sites take the address back from a stack slot (function 0x0A5180,
  listed under WHAT THE FIRST CENSUS MISSED).
MECHANISM
  if r4 != 0:               SR = r4; return
  if rec[1] == 1:           SR = 0;  return
  SR = 0; goto 0x003664
  Edge cases, each emulated:
    The test is r4 == 0, not (r4 & 0xF0) == 0. r4 = 0x400 loads SR = 0 and
    does NOT check for a switch. With r4 = a value from 0x00317C (always
    SR & 0xF0) the two tests agree.
    rec[1] is 0x00 in all 13 ROM records, so for ids 0..12 the "b == 1" exit is
    never taken: r4 == 0 always reaches 0x003664.
    The record byte is read BEFORE SR is lowered (0x003196..0x003198 run at the
    caller's mask; SR := 0 happens in the jmp delay slot).

    The resume is emulated too: for state 4 the dispatcher picks

WHY THE PAIR EXISTS
  0x002C02..0x002C12 (interrupt exit): a task switch is taken only if the
  interrupted code had I3..I0 == 0. So between 0x00317C(0x10) and 0x003190(0)
  interrupts above level 1 still run, but none of them can switch tasks; the
  switch they made due is taken at 0x0031A0. Levels 0x90 / 0xB0 / 0xE0 also
  keep out interrupt handlers up to level 9 / 11 / 14.
  The same holds for a switch the task asks for itself. 0x002EDC(id) queues
  the id through 0x003206 and switches at once only when its caller's mask
  field and [0xFFFF1290] are both zero (0x002F20..0x002F2A). Called inside a
  section with an id whose index is above the highest one ready, it returns 0
  and leaves word [0xFFFF128E] != word [0xFFFF128C]; the closing 0x003190(0)
  takes the switch (emulated end to end, test_ready).
EVIDENCE
  0x003190 tst r4,r4 sets T when r4 == 0; 0x003192 bf leaves when T = 0;
  0x00319A cmp/eq #1,r0 sets T when the byte is 1; 0x00319C bt leaves when
  T = 1; 0x0031A0 is jmp, not jsr.
  emulated: test_3190, 4 SR x 11 r4 x 6 record bytes = 264 cases; all 13 ROM

==== FUNCTION 0x00E6E4 .. 0x00E704  (16 instructions, 136 call sites in 65 census functions) ====
================================================================================
CONTRACT
  in    r4 = address of a 16-bit word (even)
        r5 = bit mask (only bits 15..0 reach memory)
        r6 = selector: (r6 & 0xFFFF) != 0 -> SET, == 0 -> CLEAR
  mem   word@r4 := (word | r5) & 0xFFFF      (SET)
        word@r4 := word & ~r5 & 0xFFFF       (CLEAR)
        One 16-bit read and one 16-bit write of that word. Nothing else.
  SR    := 0x00E0 from 0x00E6E8 to the rts delay slot, then := the exact entry
        value (T, S, Q, M included).
  out   none. r0 is not written. r2 = entry SR, r3 = new word (sign-extended),
        r6 = r6 & 0xFFFF, r5 = ~r5 on the CLEAR path. No stack.
MECHANISM
  old = SR; SR = 0x00E0
  w = *(int16 *)r4
  if (r6 & 0xFFFF) == 0:  w &= ~r5   else:  w |= r5
  *(uint16 *)r4 = w
  SR = old
  Edge cases, each emulated:
    r6 = 0x00010000         CLEAR (only the low word of r6 is tested).
    entry mask 0xF0         the mask is LOWERED to 0xE0 for the update: SR is
                            loaded with the constant, not raised to it.
    r5 = 0xFFFF8000         sets / clears bit 15 only (a sign-extended mask some
                            sites pass).
WHAT IT IS CALLED ON
  All 136 sites, r4 recovered by a whole-image dataflow over the code map
  (emu_rtos_core.py test_sites: one constant on every path at every site,
  nothing unresolved, the distribution asserted):
;     0xFFFFF42E x4    0xFFFFF462 x4    0xFFFFF482 x19   0xFFFFF630 x4
;     0xFFFFF66C x11   0xFFFFF6EA x6    0xFFFFF738 x4    0xFFFFF74E x16
;     0xFFFFF754 x32   0xFFFFF75C x5    0xFFFFF75E x12   0xFFFFF76C x19

================================================================================
CALL-SITE METHOD, AND WHAT THE FIRST CENSUS MISSED
================================================================================
METHOD  (emu_rtos_core.py test_sites; every figure below is an assertion there)
  1. Code map. Recursive descent along bt / bf / bra / bsr from each of the
     5,151 function entries of disassembly/maps/function_census.json (the only
     thing taken from that file) and from both vector tables: 286,155
     instructions. A literal-pool word is never an instruction.
  2. Dataflow. Forward over the whole image, meeting at every join. A value is
     a set of up to six constants, an address r15+k, or unknown; long slots
     addressed through r15 are followed. Function entries start with nothing
     known. A call kills r0-r7 and keeps r8-r14.
  3. A call site of X is a jsr / jmp @Rn where Rn is exactly {X} on every path.
  COMPLETENESS, per target: every aligned long equal to the address is read by
  a PC-relative load in the code map (176 / 176 / 50 / 127 / 128 longs for
  0x00317C / 0x003190 / 0x00E6E4 / 0x0BE81C / 0x0BE82C); the set of functions
  with such a load equals the set of functions with a counted site; no word
  outside the code map decodes as such a load except nine that are themselves
  pool words; a register holding one of the addresses is stored to memory at
  only six places, all r15-relative slots the dataflow follows (0x059028,
  0x05903A, 0x05A836, 0x05A846, 0x0A53A0, 0x0A5426); and of the 131 indirect
  transfers the dataflow leaves unresolved, 74 take their register from memory
  through a pointer or table, 53 from a literal that is none of the five
  (54 before the item-106 census rejected the data seed 0x011954, whose
  `jsr @r1` targets 0xFFFFFFD2)
  addresses, 3 compute it by an add and 1 has no write in reach. So the counts
  are not lower bounds for references of this kind; a call through an address
  built by arithmetic would not be seen.
  THE CONVENTION. "A call keeps r8-r14" is the Renesas C convention, not a
  fact about each callee. Measured: 3,072 of the 3,819 call targets provably
  restore r8-r14 and r15 at every exit (greatest fixed point; 0x003190 is put
  in by hand on the strength of the emulated save / resume). Allowing only
  those between the literal load and the call still resolves
;     0x00317C  366 of 404     0x003190  340 of 382     0x00E6E4  136 of 136
;     0x0BE81C  350 of 355     0x0BE82C  346 of 348
  The remainder sit in functions 0x01D31C, 0x0210DA, 0x04907C, 0x04F206 and
  0x04F368 (the pair) and 0x00DD52, 0x00DDAC, 0x00DE38, 0x00DE92, 0x010E12,
  0x00FACA (0x0BE81C / 0x0BE82C). Their in-between callees have an ordinary
  push / pop frame (e.g. 0x0BCEA4: 0BCEA4..0BCEB0 push r8..r14, 0BD4DC..0BD4EA
  pop them) but write their frame through computed pointers, which the check
  does not follow. None of the sites listed below is among them.
  FUNCTION COUNTS use the census entries as boundaries and are called "census
  functions" for that reason. The list has at least one false entry: 0x008000
  (last excerpt below).

RELATION OF 0x00E6E4 TO 0x010800, 0x010B2A AND RAM 0xFFFF2060 / 0xFFFF2064
================================================================================
By bytes there is none.
  * 0x00E6E4 is a leaf with one literal (the word 0x00E0). It contains no
    reference to 0xFFFF2060, 0xFFFF2064, 0xFFFF20A0, 0x010800 or 0x010B2A.
  * None of its 136 call sites passes an address in 0xFFFF2060..0xFFFF20A7
    (asserted in test_sites); all pass on-chip register addresses.
  * 0x010800 -> 0x010B2A -> 0x0BDA70 / 0x0BDAAC / 0x0BDB6E / 0x0BDB80 never
    executes 0x00E6E4 (asserted over 310 emulated calls in test_log).
  * What the two have in common is only the mask level: 0x00E6E4 loads SR with
    0x00E0 itself; 0x010800 asks 0x0BE81C for 0xE0.
WHAT 0x010800 / 0x010B2A DO  (r4 = 16-bit code, r5 = 32-bit datum)
  0x010800: save mask, raise to >= 0xE0, call 0x010B2A, restore mask.
  0x010B2A:
    n = guarded byte at 0xFFFF2060 (0 if the value / complement pair is bad)
    for i in 0..n-1:                       -- records at 0xFFFF2064 + 12 * i
        if guarded word at record i == code:
            if record[8] < 255: record[8] += 1
            found
    if not found and n < 5:
        record n = { code:~code , datum , hits = 1 };  n += 1
    [0xFFFF20A0] = code:~code;  [0xFFFF20A4] = datum       -- always
  So: at most five records, one per distinct code, each keeping the FIRST
  datum seen and a saturating hit count; a sixth distinct code is dropped
  except for the "last" pair. Nothing here consumes or shifts records, so
  "queue" is the wrong word for what these two functions do to it.
  WHO CALLS 0x010800  (21 sites; static, asserted in test_sites; r4 = the code)
;     after the call the same function transfers to 0x00FBA4, the endless loop -- 9 sites:
;       0x00E788 (0x4000: the interrupt trap)      0x00E7B0 (the code is the argument of 0x00E794)
;       0x00B812, 0x00B82E (0x5100)                0x00B960, 0x00B97E (0x6000)
;       0x0107E2, 0x010A02 (0x2000)                0x010B1A (0x2100 / 0x2200 / 0x2300)
;     after the call the function carries on and cannot reach 0x00FBA4 -- 8 sites:
;       0x00B02A, 0x00B2D8, 0x00B9B4, 0x00B9F8, 0x00BA20, 0x00BA56 (0x5000)
;       0x00E81C (0x8000)                          0x01009A (0x7100, in function 0x01002A)
;     tail transfers, so 0x010800 returns to the caller's caller -- 4 sites:
;       0x01027E (0x7100)    0x0106B2 (0x7000 / 0x7010)    0x0106DC (0x7100 / 0x7110)    0x010AA0 (0x9000)
  So 0x010800 is a general {code, datum} log. It records a path that ends in
  the endless loop at 9 of its 21 sites, not at all of them. What the codes
  mean: not established.
  emulated: test_log, 10 scripted calls + 300 saturation calls.
WHO ELSE HOLDS THE BLOCK'S ADDRESS
  Eleven pool words in the ROM point into 0xFFFF2060..0xFFFF20AB (asserted in
  test_sites). They belong to five functions: 0x010B2A above, and
    0x01076A  clears it all: count, last code, byte [0xFFFF20A8], the five
              records. One call site, 0x00E512.
    0x010708  returns 1 if the count, the last code or any record's code fails
              its complement check, else 0. No literal, jsr or bsr reaches it.
    0x010828  returns the last code. No literal, jsr or bsr reaches it.
    0x010870  sets the last code to 0. No literal, jsr or bsr reaches it.
  None of the five takes ONE record out or acts on what a record holds. There
  is no drain in the code that knows where the block is.
