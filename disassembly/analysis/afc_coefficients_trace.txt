INTERPRETATION (algebra only -- not an identity claim about any cell)
  The formulas are the textbook ones for a first-order-plus-dead-time model discretised with a fractional delay
  (pole Q1 = e(T/TAU), integer delay d, numerator Q5/Q6 with Q5 + Q6 = 1 - Q1) and a double target pole
  z^2 + A z + B = (z - e(WT))^2 (c = 1), whose DC gain fixes P0 = (1 + A + B)/(Q5 + Q6).  0x03286C tracks exp(-x)
  within 0.0286 on [0, 6] (largest 0.02858 near x = 1.457; pass B dense scan).  Whether the ECU designer meant
  exactly this is not something bytes can say.

MECHANISM
  T = [7474]; L = [7478]; TH = [747C]; TAU = [7480]
  if out(TAU, 0, 2^-11): Q0 = T / TAU            ; out() = 0x0BE608: 1 when x < c-w or x > c+w; edges, NaN inside
  Q1 = e([Q0])
  n  = ftrc(L) & 0xFF ; Q2 = float(n)            ; ftrc rounds toward zero; NaN / out of range saturate (emulator)
  Q3 = fmac(Q2, -T, TH)                          ; = TH - n*T in one rounding
  if out(TAU, 0, 2^-11): Q4 = (T - Q3) / TAU
  Q5 = 1 - e([Q4]) ; Q6 = (1 - [Q1]) - [Q5]
  In the live chain TH = T * L (0x031DB4), so Q3 = T * (L - n): the fractional part of L in units of T, and
  Q4 = T * (1 - (L - n)) / TAU.  Edges: TAU = 0, +-0.00048828125 exactly, NaN -> both divides skipped, Q0/Q4 held
  (emulated: 0.0004, 2^-11, next float above).  L < 0 or > 255: n = trunc(L) & 0xFF (e.g. 300 -> 44, -3 -> 253).
  In the live chain L = min(lookup 0x0AD620, 40) lies in 4.9999995 .. 21.999998 (cells x 0x3E4CCCCC fall
  just below the integers under either rounding mode), so n is 4 .. 21 and 0x032892 is called at k = 5 .. 22.
