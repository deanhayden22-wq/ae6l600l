THE THREE ANSWERS THIS TRACE WAS ASKED FOR
--------------------------------------------------------------------------------
1. SEARCH ALGORITHM.  Both searches are a LINEAR scan DOWNWARD from the last
   breakpoint (not a binary search): compare x with axis[count-1]; then
   axis[count-2], axis[count-3] ... until a breakpoint that is not greater than x.
   Cost grows with (count - index).  Neither search guards count <= 0 (0x0BECA8 MECHANISM).

2. OUTSIDE THE AXIS: CLAMP, NEVER EXTRAPOLATE.
   x >= axis[count-1]  ->  index = count-1, fraction = 0   (0BECD0 / 0BED8A)
   x <  axis[0]        ->  index = 0,       fraction = 0   (0BECD6 / 0BED90)
   Every interpolation handler returns cell[index] alone when the fraction is 0 and
   does not load cell[index+1], so the result is exactly the last / first cell and
   nothing beyond the table is read.  Emulated on 687 + 210 real records: 4,788
   1-D inputs below the first or at/above the last breakpoint and 840 2-D out-of-range
   corners all returned the edge cell.  (Which cell is returned does not depend on the
   float rounding; the scale*raw+bias the typed wrappers then apply is one fmac.)

3. 2-D ORDER AND STRIDE.  address of cell(i0, i1) = data + (i1 * count0 + i0) * size
     i0 = index on the axis at record+4 (length = word at record+0, input fr4)
     i1 = index on the axis at record+8 (length = word at record+2, input fr5)
   The axis at +4 runs along memory (adjacent cells); the axis at +8 selects one of
   count1 consecutive runs of count0 cells.  The multiplier of i1 is count0 (0BE8FA
   loads record+0 into r0; 0BEBC4 muls.w r0,r3).  count1 never enters an address.
   In C terms: data[count1][count0], indexed data[i1][i0].
   Proof by emulation: 20,658 real breakpoint cells over 210 real records equal
   data[i1*count0+i0]; in 158 of those records (14,622 cells) the transposed order
   data[i0*count1+i1] would have produced a different number.
   Real example, record 0x0AA834 (count0 18, count1 17, uint16, scale 0.125):
     fr4 above axis0, fr5 below axis1 -> 0.0     = data[0*18+17] (raw 0)
                                         transposed would be data[17*17+0] = raw 7172 -> 896.5
     fr4 below axis0, fr5 above axis1 -> 983.875 = data[16*18+0] (raw 7871)
