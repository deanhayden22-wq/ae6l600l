ANSWER
  0x03D856 -- a per-step angle scheduler for four output channels.  Its own body reads no calibration; its
  call tree reads ONE cal long (0x0CBDB4, no definition names it) -- see "Lever" below.
    * It runs once per pass of task 5 (0x04A94C, itself run only while byte [0xFFFF8EDC] == 0), after the
      fuel-chain calls 0x033304 / 0x032B10 / 0x031D1E, with r4 = the low byte of a long that 0x00E486 dequeued
      (0x00FE22, two-slot queue at 0xFFFF5B70; the producer is not decoded).  The byte is a step index: angle =
      30 * (index, reduced once by 24 if >= 24) in 16.16, on a cycle of 720 (0x02D00000 = 720 << 16).  "720 =
      one four-stroke cycle in crank degrees" fits every constant here but is NOT established by these bytes.
    * Four 40-byte channel records at 0xFFFF7DA8 (k = 0..3) have target angles 0 / 360 / 180 / 540 (table
      0x063E20), channel byte k and hardware-channel byte 0x063E30[k] = k -- written by 0x03D708, which runs
      only on the byte [0xFFFF8EDC] == 0 branch of 0x047C40 (task 10's init).  The record power-on state when
      [8EDC] != 0 at that init is not established.
    * Per call, for each record: distance d = target - angle folded once into (0, 720] (for in-range angles).
      d == 720 (the step IS the target) re-arms the record: state 0, mode byte from table 0x063DFC (0 when
      byte [0xFFFF726C] == 1, else 1), cut flag = bit (1 << k) of word [0xFFFF7D80], counted flag cleared.
      An armed record (state 0) first tests its hardware status byte [0xFFFF429B + 28*hw]: non-zero -> nothing
      changes, whatever d is.  With status 0: d <= 100 -> state 2 ("missed"); 100 < d <= 720 -> counted once
      per arming (rec+3 == 0: S+0 += 1 saturating, rec+4 = S+0, rec+3 = 1), then FIRED only if the cut flag
      is clear (so normally at the re-arm step itself, d = 720); d > 720 needs a target outside [0, 720) and
      does nothing.  A cut record is counted under exactly the same gates and never reaches 0x03D50E, the
      +28 copy, 0x03D582 or the fire function.  Firing = compute a pending angle (rec+32) and duration (rec+24)
      and call the mode's fire function, 0x03E168 (mode 0) or 0x03DFC8 (mode 1), which pass (hw, duration,
      angle) to the per-hardware-channel drivers 0x009A72 (mode 0) / 0x009B2C (mode 1) and in other sub-states
      call 0x009C38 / 0x009D48 (what the four drivers do is NOT decoded; 0x009D48 loads on-chip register
      addresses 0xFFFFF66C / 0xFFFFF440 / 0xFFFFF666).  A record in state 1 re-fires only when rec+6 == 1 (set
      each pass by 0x03D552 while [726C] == 1, and by 0x03E168 on its "too early" exit).  Step skips
      (delta != 1) go through 0x03DB16, which itself stores the current mode index and mask into S+9 / S+10,
      so in a resync pass 0x03DD8E / 0x03DE6E are NOT called even if the mode or mask changed (emulated on
      the unstubbed tree); otherwise a mode change goes through 0x03DD8E and a change of [0xFFFF7D80] through
      0x03DE6E.
    * Init request (byte [0xFFFF7E55] == 1): one call clears the state and per-record fields, gives every
      record whose distance lies in [m, 720) a count 1..4 and state 0 (m = max(0, trunc(f32 [0xFFFF72B4] *
      65536))), and then runs the normal per-record loop in the SAME call -- so the d == 720 record is re-armed
      and counted at once, and armed records with d > 100 fire in the init call itself (emulated: init at
      angle 0 with [72B4] = 0 -> counts 4, 3, 2, 4 and all four records fired).  The request is raised by
      0x03D708 and by 0x03DBF4 (from 0x04AE82 when its r4 == 1; when that runs is not established).
    * Mode 1 (byte [726C] != 1): pending duration = 4 * f32 [0xFFFF7290 + 4k] (x [0xFFFF7DA4], which 0x03D68C
      sets to 1.0 every pass before 0x03D856 -- the only writer found), pending angle = 180 + f32 [0xFFFF7280].
      Mode 0 (byte [726C] == 1): only the ANGLE depends on the record's event number n (word rec+4, from the
      saturating counter word [0xFFFF7E48]): one of four floats [0xFFFF72B4..72C0] by three byte break points
      [0xFFFF72D3..72D5].  The duration is the same for every record and every n: rec+24 = trunc(clamp([7300] +
      f32 [0xFFFF72FC] * [72E0] * [72E4] * f32 [0xFFFF72EC] * [72F4] * [72E8], 0, 262136) * [7DA4] / 0.25),
      because 0x02FCBA / 0x02FB1C are 3-instruction getters of [72FC] / [72EC] that ignore r4.  [72E0] / [72E4] /
      [72E8] are
      written earlier in the same task pass by 0x02F974 (only while byte [0xFFFF65F1] == 0 and [726C] == 1)
      from the 1-D uint8 tables 0x0AC34C / 0x0AC360 / 0x0AC374 looked up on f32 [0xFFFF620C] / [0xFFFF64D8] /
      [0xFFFF6364] (the third table is 1.0 everywhere in all three bins).
    * Driver angle: fr4 = fold(30 * byte [0xFFFF7E54] - 10 - x) / 65536 degrees, fold = -720 once if >= 720,
      +720 once if < 0, byte [7E54] = the UNREDUCED step byte (so a byte >= 48 gives angles past 720); x = 0

  0x02EB02 -- one pass of a six-word serial-EEPROM write-back with verify and retry.  NOT a lever.
    * When: called only by 0x02E8C0 (called by 0x049A7A, the event-5 handler that runs only while
      [0xFFFF8EDC] == 0 -- revlim_freeze_gate_trace.txt), and only while byte [0xFFFF8E98] != 0 (writer at
      0x05AD5C, not decoded) and the phase bytes say: phase A done ([7263] == 1), phase B not ([7264] != 1).
      Phase A (0x02E968) builds six words (0x02EA98: words [0xFFFF24E8], [0xFFFF24EC], 0, 0, byte
      [0xFFFF24F0] << 8, and a check word making their 16-bit sum 0xAA55), reads EEPROM words 483..488 and sets
      flag byte [0xFFFF725D + k] = 1 where word k differs.  If none differs it marks phase B done itself, so
      0x02EB02 runs only when at least one word must be written.
    * Each pass: on the first pass of a session (marker byte [725A] != 0x5A) the session-start writes come
      FIRST ([725B] = first flagged index, [725C] = [7267] = [7244] = 0, [725A] = 0x5A), even when the pass then
      backs off.  Back off ([7258] = 0, return, no serial traffic) unless lock byte [0xFFFF6C48] is 0 or 0xEE;
      poll busy (0x006884); on the 7th consecutive busy pass give up WITHOUT the disable command; otherwise, if
      the state byte [725C] is 2 (all written) or 3 (gave up), or f32 [0xFFFF4130] < 6.0 (that cell is the
      "Battery Output" axis input -- step-4 item C7, re-derived from bytes), send EWDS and finish; else take
      the lock (0xEE is written ONLY here, on a ready, non-aborting pass), send EWEN, verify the last write by
      READ (mismatch: rewrite; after the 3rd failed verify -- cal byte 0x0C472C = 3 in all three bins -- state
      3), and on a match write the next flagged word k to address 483 + k (WRITE) and park the index on the
      next set flag.  Finish (abort or busy timeout) = lock := 0, [7264] = 1, [725A] = 0, and [7265] = 1 when
      f32 [0xFFFF4130] < 6.0 (skips phase C).  Phase C (0x02ED88) then stores the outcome byte [0xFFFF7268]
      (1 = busy timeout or gave up, 0 = all written; anything else: no outcome, only [7265] = 1) with its
      value:~value copy word [0xFFFF3154].  On every call 0x02E8C0 copies that word's high byte into [7268]
      when the pair is consistent, and otherwise REBUILDS the word from [7268].
    * The command words follow the 93Cxx Microwire format exactly (start bit, 2-bit opcode, 10-bit address,
      16-bit data; type byte [0x0C0080] = 1 selects the 10-bit layout): EWEN 0x13000000, EWDS 0x10000000,
      READ 0x18000000 | a << 16, WRITE 0x14000000 | a << 16 | data.  That identification is from the command
      encoding; the bus is on-chip peripheral bytes 0xFFFFF01A / F01B / F01C plus port words 0xFFFFF738 /
      F76C (which pins: not established).
    * Reaches: non-volatile storage and a write-outcome flag.  Not fuel, not spark, not an actuator.  The
      calibration it and its callees read: the retry limit 0x0C472C = 3 (its own body) and the command-layout
      byte 0x0C0080 = 1 (through 0x006B5A); both identical in all three bins.  What the stored words mean (the
      cells 0xFFFF24E8 / 24EC / 24F0) is not established.

MECHANISM  (dist(a, t) = t - a, plus 720<<16 when the difference is not > 0: always in (0, 720] for a, t in [0, 720))
  seg   = r4 & 0xFF;  delta = seg - S+12 (zero-extended), +24 if negative;  S+12 = seg
  s     = seg - 24 if seg >= 24 else seg          (once: seg 48..255 gives s >= 24 and angles past 720)
  ANGLE = 30*s << 16
  if S+13 == 1:                                    -- INIT PATH (falls into the common path below, SAME call)
      S+13 = S+9 = 0; S+10 = 0; S+0 = 0; S+4 = 0     (S+8 is NOT touched here)
      every record: +0 +1 +2 +3 +6 +7 +17 +36 = 0, +4 = 0, +20 = +24 = 0, +28 = +32 = 720<<16
                    (+8, +12, +16 and the pads +13..15, +18, +19, +37..39 are not written)
      every record: d = dist(ANGLE, +8);  0x03D50E(rec)  (+0 is 0, so +32 = trunc([0xFFFF72B4] * 65536):
                    the event number is 0 and 0 <= every break point);  m = max(0, +32)
                    if m <= d < 720<<16:  S+0 = sat(S+0 + 1);  +4 = floor((d - m) / 180deg) + 1 (1..4);  +3 = 1;  +2 = 0
                    else:                 +4 = 0;  +3 = 0;  +2 = 2
      (S+9 = 0 and S+10 = 0 now, so below 0x03DD8E runs when byte [726C] != 1 and 0x03DE6E when the mask is
       non-zero; the record with d == 720 is re-armed and counted, and armed records fire, in this call)
  else if delta != 1:  0x03DB16()                  -- resync (contract below); it stores S+9 = 0x03D4F6() and
                                                      S+10 = word [7D80] itself, so the two tests below find
                                                      them equal and neither handler runs in a resync pass
  idx = 0x03D4F6() (0 when byte [726C] == 1, else 2)
  if idx != S+9:  0x03DD8E(ANGLE, sext(byte 0x063DFC[idx]));  S+9 = idx
  msk = word [0xFFFF7D80]
  if msk != S+10: 0x03DE6E(ANGLE, msk);  S+10 = msk
  for each record:
      d = dist(ANGLE, +8)
      if d >= 720<<16 (signed):                    -- RE-ARM: the step is the target
          +17 = 0; +2 = 0; +7 = 0; +0 = byte 0x063DFC[S+9]; +1 = (S+10 & (1 << +12)) != 0; +3 = 0
      T = 0x063E00 + 16 * sext(+0)
      state 0:  if byte [0xFFFF429B + 28 * +16] != 0:  skip (stay armed; nothing changes, whatever d is)
                if not d > T.l4 (100):  +2 = 2;  skip
                if d > T.l0 (720):      skip      (needs a target outside [0, 720): unreachable with 0x063E20)
                if +3 == 0:  S+0 = sat(S+0 + 1);  +4 = S+0;  +3 = 1     (at most once per arming)
                if +1 != 0:  skip                 (cut: counted under the same gates, never fired)
                0x03D50E(rec);  +28 = +32;  FIRE
      state 1:  if +1 != 0 or +6 != 1:  skip;  FIRE
      other:    skip
      FIRE  = 0x03D582(rec);  call long [T + 8] with r4 = rec, r5 = d
  Edge cases (all emulated): equal angles give d = 720 (re-arm), never 0; d = 100 exactly -> state 2,
