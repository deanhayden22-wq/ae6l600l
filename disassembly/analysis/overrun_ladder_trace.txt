  * 0x03AE5A runs, in order: 0x03B3DA (counter), 0x03AF88 (rungs), 0x03AE6C (tier + mask), 0x03B62C (tail).
    It is reached only through 0x03AB90 (bra), called once per run of 0x04907C, which is the body of RTOS task 9
    (entry 0x00E448).  Task 9 is activated on one call in eight of 0x010D10, the tail of the interrupt handler
    0x00F518 (vector 192, rtos_core_trace.txt stub table); that handler's timer is loaded with period register
    2499 (2500 counts) and control word 0x00C0.  So one count of [7CAA] = 8 handler entries = 20,000 counts of
    that timer.  In milliseconds that is 8 ms ONLY IF the timer clock is P-clock/8 at a 20 MHz P-clock -- neither
    fact is in the ROM (NOT ESTABLISHED, N3; it agrees with the ~8 ms per count of item 103's logs).
  * [7CAA] (u16) counts consecutive passes of 0x03AE5A in which every count condition holds (below); any pass
    that fails one zeroes it.  On the other "immediate" path it is set straight to rung 4 [7C98].

    [7C78] alone, and is also 1 when x or the sum is NaN; else 0 when [7C78] > x; else ([7C9E] == 1).  With
    [7C6C] >= 0 and nothing NaN that reads: set when x >= [7C78] + [7C6C]; while [7C9E] == 1 it stays set down
    to x >= [7C78]; below [7C78] it is 0.  (A negative band would keep it set below [7C78]: emulated.)  [7C78]

    band (batch-2 0x03AB94 contract: once its latch [7C70] has been written, [7C6C] is one of 200 .. 2100, so

==== BOTTOM LINE: FROM LIFT TO CUT TO RESUME ====
  Times in seconds below assume 8 ms per count, which is NOT established from bytes (N3).  "x" is f32 [6624],
  compared in rpm units by the base-defined band edges and resume table (batch-2 E5 / E9 / E10).
  1. Gate opens.  [64F5] goes to 1 (f32 [64D8] < 0.001 for >= 3 runs) while [67EC] >= 750, [5E98] == 0,
     [972E] == 0, none of the CLEAR conditions, and x >= [7C78] + [7C6C] (entry needs the resume threshold
     PLUS the band; [7C6C] = 200 or 1000 base, +100 / +1000 adders: batch-2 E14 / E15).
  2. From that first qualifying pass 0x03AF88's selection section stops ([7C9E] goes to 1 in step 1 of the
     sequence; the section runs only while [7C9E] == 0), so base / ext1 / ext2 / adds are frozen at the values of
     the last pass BEFORE the lift: the band of x at that moment, the [6810] selector and the [5DB8] side.  The
     one thing that can still move a rung is 0x03AF88's section-2 arm ([7C80] = 250 when [65FC] >= 500,
     [6350] >= 40, flag, [7EED] == 1 and [7CAA] < [7C92]; batch-2 E8), which raises M to 250.
  3. [7CAA] = 1, 2, 3 ... one per pass.  tier 1 (channel 0 cut) at [7CAA] = base (+625 with the adds), tier 2
     (channels 0-1) at base + ext1, tier 4 (all four channels) at base + ext2.  If base + ext1 >= base + ext2
     tier 2 is skipped; tier 3 never happens.  Any failing pass (pedal gate, window, a CLEAR flag) zeroes
     [7CAA] and the tier on that same pass -- the delay starts again from 0.
  4. Cut held: while counting continues the tier stays 4 down to x >= [7C78] (hysteresis on [7C9E]), given
     [7C6C] >= 0 (with a negative band it would stay down to x >= [7C78] + [7C6C]: E2).
  5. Resume: the first pass with x < [7C78] (or any failed condition) gives [7C9E] = 0, [7CAA] = 0, tier 0,

     0x041BE4 run (and any run between x falling and that pass) arms [8032] / [8033], because it tests the
     tier its previous run stored in [8034] (E15, E20).  Re-entry needs x >= [7C78] + [7C6C] again.
